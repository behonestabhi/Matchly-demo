# Project Status — what's implemented vs. scaffolded

This is an honest accounting of the codebase so whoever receives it knows exactly
what they're getting. Read it before assuming any component is production-ready.

> **Headline:** this is a complete, coherent, runnable monorepo for the full
> Matchly architecture (8 Spring Boot apps + a Python AI service + a React
> frontend + Kafka/Postgres/Redis + K8s/Terraform/CI). The AI service and the
> frontend are **built and verified locally**. The Java services are **written to
> compile and run** but were **not compiled in this environment** (no Maven/Docker
> was available here) — they build via the Dockerized Maven stage. It is **not yet
> integration-tested end-to-end** as a running stack.

## Build environment note
Generated on a machine with **Python 3.13, Java 17, Node 24 — but no Maven and no
Docker.** Consequences:
- ✅ AI service: dependencies installed, **30 unit/contract tests pass**, all
  endpoints smoke-tested via FastAPI `TestClient`.
- ✅ Frontend: `npm install` + `npm run build` **succeed** (TypeScript strict).
- ⚠️ Spring services + gateway: **not locally compiled** (no Maven). Code targets
  Spring Boot 3.2.5 / Java 17 and was written carefully for correctness, but it
  has not been run through `javac`/`mvn`. Expect to fix minor issues on first
  `mvn package` / `docker compose build`.
- ⚠️ K8s / Terraform: syntax-checked only; **not applied** to a cluster/cloud.

## Build history note
The Java services were generated by parallel builders; a few were interrupted
mid-run and **completed by hand afterward**: `job-service` (full Java layer),
`matching-service` (service + Kafka consumer + controller + REST clients + DTOs),
`analytics-service` (REST controller + query service), and `candidate-service`
(added the in-cluster `/internal/candidates/{id}/matching-profile` that matching
depends on). The `AiDtos.ScoreRequest` in matching-service was corrected to match
the AI service's real `/internal/score` schema.

## Cross-service contracts (the integration-risk areas)
These were designed to line up; verify them first when you stand the stack up:
- **Event envelope** `{eventId,eventType,occurredAt,correlationId,version,payload}`
  is shared; `occurredAt` serializes as ISO-8601 (spring-kafka registers
  JavaTimeModule). Consumers read JSON values via `StringDeserializer` or a typed
  `JsonDeserializer` — both read the same bytes.
- **Scoring flow:** `ApplicationSubmitted` → matching consumes → fetches candidate
  (`/internal/candidates/{id}/matching-profile`) + job (`/api/v1/jobs/{id}`) →
  AI `/internal/score` → persists + emits `MatchScored`.
- **AI service is HTTP-only** (no Kafka). Java services orchestrate; AI computes.

## Known simplifications / deliberate gaps
- **OAuth2 login** in auth-service is **stubbed (HTTP 501)** — schema/entities
  exist; the provider handshake is not implemented.
- **Resume storage** writes to a local directory as a **stand-in for S3**.
- **Perimeter auth:** downstream services trust gateway-forwarded
  `X-User-Id`/`X-User-Roles` headers and do **not** re-verify the JWT.
- **Matching idempotency** relies on the score upsert (replays re-score the pair).
- **Analytics** consumes `MatchScored`/`QuestionsGenerated` but does not yet
  project them into dedicated read models; report export is **CSV only**.
- **ML predictor** trains on synthetic data at AI-service startup (cold-start);
  `pgvector` + `sentence-transformers` activate when available, else deterministic
  fallbacks are used (so it always runs).
- **No end-to-end integration test** of the running stack yet.

## Recommended first steps for the recipient
1. `cp .env.example .env`, set a real `JWT_SECRET` (and an LLM key if you want
   live interview generation; otherwise the offline template generator is used).
2. `docker compose up --build` (this runs the Maven builds inside Docker).
3. Expect to fix a few first-compile issues in the Java services; the AI service
   and frontend should come up clean.
4. Open the frontend at `http://localhost:8088`, gateway at `http://localhost:8080`,
   AI docs at `http://localhost:8000/docs`, and each service's `/swagger-ui.html`.
5. Walk the smoke path in [docs/ROADMAP.md](docs/ROADMAP.md): register → post job →
   upload resume → apply → see ranked candidates → generate interview questions.
